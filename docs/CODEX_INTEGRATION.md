# Production Codex Runner

`middle-man codex run` is the user-facing path for one task in a real repository. Dry-run performs local preparation only. A confirmed read-only production smoke test has passed; the live path remains behind explicit `--confirm-external-service`. The confirmation option sends the task and optional source-free locator to Codex; Codex may then read repository files with native tools and transmit their contents to its external service.

```bash
middle-man codex run --repo . --read-only --dry-run "Explain how preemption works"
middle-man codex run --repo . --workspace-write --dry-run "Fix the scheduler bug and run tests"
middle-man codex run --repo . --read-only --confirm-external-service "Explain how preemption works"
middle-man codex run --repo . --workspace-write --confirm-external-service "Fix the scheduler bug and run tests"
middle-man codex isolation-preflight
```

Quote the positional task as one shell argument. Exactly one of `--read-only` and `--workspace-write` and exactly one of `--dry-run` and `--confirm-external-service` are required. `--model` defaults to `gpt-6-sol`; `--effort` defaults to `high` and accepts `low`, `medium`, `high`, or `xhigh`. `--timeout` defaults to 360 seconds and protects the process, not model turn count. No benchmark `TaskSpec` or frozen snapshot is involved. One confirmed product task starts at most one Codex process; there is no retry, fallback run, or A/B comparison.

The runner validates that `--repo` is a Git repository root, reads the existing BALANCED/6000 context selection, builds the existing source-free offline locator, and applies the locked AUTO decision. It disables index-cache writes and checks HEAD, porcelain status, and Git-visible file hashes before and after preprocessing. For a read-only task, AUTO appends the locator only when candidate source is at least 10,000 heuristic tokens and selected paths exist. Otherwise it bypasses. Every workspace-write task bypasses, even when the candidate estimate crosses the threshold. A bypass leaves the UTF-8 task bytes unchanged; a used locator appends only the existing locator wrapper. There are no generated `AGENTS.md` files, MCP registrations, Context Pack source excerpts, benchmark footers, or offline edit anchors in this path. Codex itself may still see repository-authored guidance already present in a real repository; Middle_Man does not create or modify it.

The dry-run prints a redacted command shape, not the prompt, and makes zero model calls. Its in-memory audit contains the repository root, SHA-256 task hash, UTF-8 task length, mode, CLI identity, model/effort, candidate/selected estimates, AUTO decision and reason, locator estimate/hash when used, selected paths, selector fingerprint, model-visible Middle_Man estimate, and `external_calls=0`. It does not persist the task, prompt, source excerpts, or audit by default. The heuristic estimates are not Codex-reported usage or billing tokens.

For a confirmed run, Middle_Man adds `--json` to the Codex invocation and parses its JSONL events with the existing shared Codex parser. It records available thread ID, final message, input/cached/output/reasoning usage, native calls, explicit reads, unique files, rereads, searches, and listings. Production-only telemetry also counts content-producing search commands, file-targeted searches, repository-wide searches, file-listing searches, Git inspections, and unclassified commands. It records safely identifiable repository-relative search targets independently of explicit reads. A search command requests content; this does not prove its output was read by the model. Unsafe, outside-root, or ambiguous targets are omitted. For a used locator, the result separately reports locator paths explicitly read, locator paths targeted by search, and non-locator paths targeted by search. Directory targets are not attributed to each file inside them. The shared Phase 22 parser and its historical metrics are unchanged.

Missing provider fields remain `null`. A malformed line, missing final result, nonzero exit, timeout, interruption, spawn failure, or unexpected MCP event yields a structured failure with any partial observations retained. Stderr is captured in memory but only its hash/size enter the result audit; raw events are not printed. The final answer is printed separately. No result file is written by default; `--json` emits result metadata and the final answer to stdout, so users should handle that output as task data. `--save-audit` is an opt-in local receipt under the ignored `.middle_man_cache/codex_runs/<run-id>/result.json`; it records a local run ID, task hash/length, routing decision, aggregate telemetry, safe relative paths, usage, timing, and integrity metadata. It omits task and prompt text, source excerpts, raw events, full commands, search terms, and final answer. `--save-audit` is unavailable in dry-run mode.

A confirmed read-only run uses `-s read-only` and must finish with the same HEAD, porcelain status, and Git-visible file digest it had before preprocessing, even if the worktree started dirty. A change is reported as `READ_ONLY_INTEGRITY_FAILURE`; Middle_Man never restores it silently. Workspace-write uses `-s workspace-write` and may change the real repository. Its result records before/after HEAD and status plus paths whose Git-visible content changed relative to the initial user state. Middle_Man never runs `git reset`, `checkout`, `clean`, `commit`, or `stash` for the user.

The locally inspected Codex CLI documents `--no-daemon`, `--ask-for-approval`, `--strict-config`, and the `exec` options `--ignore-user-config`, `-C`, `-s read-only|workspace-write`, `--ephemeral`, `-m`, `-c`, and `--json`. The runner uses those flags and the established `model_reasoning_effort` config key. It adds no MCP configuration. The first authorized read-only production smoke test passed at HEAD `0f20a2650d171dff14f875f0273c6fd18d6547ba`: AUTO used the locator; candidate, selected, locator, and model-visible Middle_Man estimates were 129,499, 5,971, 200, and 249 heuristic tokens. Codex reported 322,353 input tokens (277,504 cached), 2,484 output tokens, and 480 reasoning-output tokens. Native telemetry reported 17 calls, 0 explicit reads, 17 searches, and 0 listings; elapsed time was 82.562 seconds. The repository stayed unchanged and no MCP calls occurred. The 322,353 input-token figure is an **unpaired observation**, not a savings percentage. The new search telemetry was added afterward and was not measured in that historical smoke test.

A controlled real-repository read-only A/B is a future experiment, not part of the smoke test: exactly two separately authorized calls against the same repository, task, model, and effort. Baseline receives the original task; Middle_Man receives the original task plus AUTO locator. Compare Codex-reported input and native exploration, while preserving each run's integrity evidence. No such A/B was run in this phase.

## Production Isolation

The first complete real-repository two-arm production attempt is historical **INVALID_PAIR**. The Middle_Man arm used account-level Codex Apps/MCP, including `codex_apps` connected GitHub search/fetch and MCP resource activity, while native repository exploration was zero. Baseline and Middle_Man input were 365,918 and 772,901 Codex-reported tokens, respectively. **These figures must not be compared as a token-savings result:** tool availability differed materially. This is separate from the earlier one-sided invalid attempt and does not rewrite either record.

On installed `codex-cli 0.155.0-alpha.16.3`, `--ignore-user-config` alone did not prevent that observed hosted/account-level Apps access. The production `LOCAL_NATIVE_ONLY` policy now adds per-process `-c features.apps=false` and `-c features.plugins=false` to the shared invocation builder used by preview and confirmed execution. CLI discovery locally checks that both switches produce `false` in `codex features list` and fails closed otherwise. Normal user configuration, plugins, connectors, and credentials are not changed. The optional `mcp_servers.codex_apps.enabled=false` and `orchestrator.mcp.enabled=false` keys were not independently validated by a no-inference command in this CLI and are not passed as unverified overrides. No Middle_Man or other MCP server is registered in the production command. Future baseline experiments should call the same production invocation builder with the original task to preserve connector parity; no A/B runner is added here.

`middle-man codex isolation-preflight` makes no model call and reports version, effective Apps/plugins switches, unsupported optional overrides, ignored user config, absent Middle_Man MCP registration, and command-level policy status. Production JSONL handling now invalidates observable MCP tool calls, resource lists/reads, and app/connector/plugin activity with `UNEXPECTED_EXTERNAL_TOOL_ACTIVITY`; completed MCP calls retain the more specific `UNEXPECTED_MCP_ACTIVITY` reason. Native shell/search/file commands are not classified as external. The optional receipt stores only activity categories/event names, not connected content or raw events. **Command-level isolation is locally verified; runtime isolation remains unverified.** One separately authorized isolated runtime smoke test is needed before another A/B.

## Prospective A/B Correctness

Future production A/B answers use a local semantic review, implemented in `middle_man.gateway.codex_runner.correctness`. A reviewer checks the answer's meaning and records supporting answer spans for six core concepts: conservative explicit reads, searches remaining searches, production event flow, search classification, safe relative targets, and separate locator read/search coverage. The review also identifies the four production implementation areas and confirms that an optional receipt omits the full task, constructed prompt, source excerpts, raw events, full commands, search terms, and final answer. Material factual errors fail the answer even when it names every function. A pass requires all six concepts, all four areas, all seven privacy omissions, and no material error. The scorecard verifies that cited spans occur in the answer; it does not infer semantic truth from keywords. The reviewer is responsible for checking that each span actually supports the claimed concept.

Exact identifiers such as `classify_search_command`, `summarize_searches`, `parse_production_events`, `run_codex`, `sanitized_receipt`, and `save_audit` increase the diagnostic symbol-precision score but are not mandatory merely because the task asks for main modules and functions. An exact identifier becomes a gate only when the frozen task explicitly requires that identifier by name. The prior one-sided real-repository attempt remains **INVALID_PAIR** because no Middle_Man side ran; its condensed baseline answer passes this prospective semantic rubric, but the historical classification and observations are not changed. This rubric is local-only and is not wired into the production runner or Phase 22 benchmark evaluators.
