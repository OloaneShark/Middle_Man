# Offline Source-Selection Quality Study

**Outcome: reject the experimental candidate for further Codex testing.** This is a local, deterministic path-selection comparison, not a model run, token-savings result, or production policy. The [full source-free diagnostics](source_selection_shadow_result.json) can be regenerated with `python -m scripts.evaluate_source_selection_shadow --save`. Production AUTO, the selector, the frozen corpus, calibration receipts, and the rejected locator-quality gate were not changed.

## Method

The 24 unlabeled tasks remain exactly as frozen in `tests/fixtures/locator_shadow_corpus.json`: four each of narrow component, multi-component architecture, cross-cutting feature, test-focused, generic broad, and explicit anchor. Both selectors ran on the same clean source commit `0680a1cb8812d35b17ebd628de7ffba95798da7f` with balanced mode and a 6,000-token source budget. The current selector fingerprint remains `3a4213e19944220c02b1897e1a05a584d61bbd00e91cbf5a9e38cc07976bf555`. The archived V2 M01 locator was separately reproduced on its original `db187e0f48f54222dd250502a2e40b7f1fb16401` source snapshot; the two source commits were not silently pooled.

The experiment-only `CodeAnchorContextBuilder` changes **candidate ranking only**. It removes an `exact_symbol` boost when a natural-language word happens to equal a source symbol but the query did not provide a code-shaped identifier, explicit symbol, path, or trace anchor. Dotted, underscored, and CamelCase identifiers retain their boosts. The production range allocator and 6,000-token budget are reused unchanged. Graph neighbors are generated by the production relevance engine before the shadow boost is removed; this experiment does not rebuild that graph. This was motivated by ordinary M01 prose (`CLI`, `read`, `context`) matching symbols in unrelated tests and infrastructure. It is not a quality gate and is not wired into AUTO.

The comparison records candidate counts and top-ten ranked paths, full selected/added/removed path lists, direct versus weak signal coverage, graph clusters, test/source counts, evidence duplication (selected paths with no novel query term), source-cost estimates, and omission reasons per task. These are deterministic diagnostics. The original M01 prospective semantic rubric's `source_refs` supply an **existing source-grounded reference set** for that one task; Codex search targets are treated as exploratory evidence, not ground truth. Other corpus tasks remain unlabeled, so a changed path or better structural metric is not called a correctness gain without review.

## Why M01 Selected Those Paths

The archived V2 M01 locator selected 14 paths and used 5,999 of 6,000 estimated source tokens. `RelevanceEngine` extracts lexical terms and identifiers from the whole prose request. Exact-symbol signals weigh 95, filename terms 28, symbol terms 17, and graph/test links add further signals. In M01, `CLI` has four exact-symbol matches. That pushes `tests/test_codex_live_runner.py` (rank 1, score 267), `tests/test_codex_runner.py` (rank 2, 229), `tests/test_phase_23_claude.py` (rank 3, 193), and `tests/test_phase_23_2_runtime.py` (rank 5, 158) upward; exact matches also make them selection anchors with required ranges. `middle_man/mcp/gateway.py` ranked 4 (175) through its `context` symbol and lexical/graph signals. The graph pass adds imports, importers, and related tests; range allocation then favors required anchors and novel signal coverage per source cost before spending the remaining budget on depth. This explains the Claude, MCP, and benchmark infrastructure paths without claiming that every such path is irrelevant.

The central `codex_runner/execution.py` was selected (rank 8, score 131), as were `codex_runner/infrastructure.py` and `codex_runner/audit.py`. But `codex_runner/runner.py` ranked 15 (96; proposed cost 1,273), `cli/codex_run.py` ranked 16 (95; cost 1,949), and `codex_runner/events.py` ranked 30 (82; cost 497). All were eligible, then recorded `context_budget` omissions after the allocation reached 5,999 tokens. `codex_runner/isolation.py` ranked 63 (58), below the top-50 candidate cap; `codex_benchmark/offline_auto.py` ranked 83. `context_builder.py` was eligible at rank 41 but its proposed 5,858-token cost was not affordable late in allocation. The [diagnostic path rows](source_selection_shadow_result.json) record terms, exact-symbol signals, ranks, scores, import/test links, proposed costs, selection phases, and budget/omission decisions for every archived selected path, rubric reference, and searched path.

## Corpus Comparison

| Archetype | Tasks changed / 4 | Direct-term coverage up / down | Tasks with fewer tests |
| --- | ---: | ---: | ---: |
| Narrow component | 1 | 0 / 1 | 0 |
| Multi-component architecture | 3 | 1 / 1 | 2 |
| Cross-cutting feature | 4 | 0 / 1 | 1 |
| Test-focused | 3 | 0 / 2 | 2 |
| Generic broad | 4 | 0 / 0 | 1 |
| Explicit anchor | 1 | 0 / 0 | 0 |

On M01, the candidate selected 9 paths and 5,859 estimated source tokens. It added `cli/codex_run.py` and `codex_runner/events.py`, removed three peripheral tests plus MCP/context files, and covered 4/7 rather than 2/7 of the pre-existing M01 source references. It still omitted `codex_runner/runner.py`, `codex_runner/isolation.py`, and `offline_auto.py`; it added `codex_benchmark/runner.py`. Direct query-term coverage **fell from 12 to 10 terms**, although the selected graph became less fragmented (three clusters to two). This is mixed, not a completed architecture trace.

The broader regressions matter more than the M01 gain. M02 lost `mcp/gateway.py` and other flow paths. Test-focused T01 fell from five selected tests to two and from four direct query terms to three; T03 fell from two tests to one and from seven direct terms to six. Narrow N04 and cross-cutting C04 also lost one direct term. C04 showed similar `CLI` pressure, but the shadow change did not preserve its direct-term coverage. E01-E03 and narrow N01-N03 stayed unchanged, while E04 added one path without losing its explicit anchor. Several tasks became more graph-connected only because they selected fewer paths; connectivity alone is not quality. Candidate/source token estimates and path counts are local costs, not Codex usage.

**Decision:** the code-anchor hypothesis is plausible for the M01 false positives, but this implementation is not a defensible general improvement across the frozen corpus. Keep it shadow-only as a reproducible negative result; do not activate it or spend controlled Codex calls on it. No new threshold, policy #2, or reinterpretation of the V1/V2 token observations follows from this study. A future local investigation would need source-grounded labels across more task families and a design that preserves test-focused evidence before proposing another external experiment.
